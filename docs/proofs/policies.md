# Proofs for the precision policies and the local backend

Status: written in work package 0.3b (lane m0-proofs-ideles), not yet reviewed. Checked numerically by
`proto/policies_checks.py`. Covers the items of `SPEC.md` section 4.4 left open in `proofs/precision.md` ("Still to

## 0. Notation and what is used

`Zhat`, finite ball `a + N Zhat` (`a` rational, `N` rational, `N >= 0`) and `gcd` of rationals are as in
`proofs/precision.md` (lines 9 to 11). For rationals `x` and `R > 0` we write `R | x` when `x/R` is an integer, and
`R | 0` always. For balls of positive radius, `R Zhat` is inside `R' Zhat` exactly when `R' | R` (`precision.md`,
Proposition 3(3), line 67). "Finer" and "coarser" refer to this order, not to size.

From `proofs/precision.md` we use: Lemma 1 (`R Zhat ∩ Q = R Z`, line 13), Lemma 2
(`N Zhat + M Zhat = gcd(N, M) Zhat`, line 20), Proposition 1 (sum, line 27), Proposition 2 (product and its
tightness, line 34), Proposition 3 (set predicates, line 59), Proposition 5 (scaled residues, line 94), Proposition
6 (conversion to the scaled form and exact scalars, line 106).

Two elementary facts about rational gcds are used repeatedly; both follow from the definition (the non-negative
generator of the subgroup of `Q` generated).

- (G1) If `s > 0` is rational then `gcd(s x, s y) = s gcd(x, y)`: multiplication by `s` maps the group generated by
  `x, y` onto the group generated by `s x, s y`.
- (G2) If `t | x` and `t | y` then `t | gcd(x, y)`: the generator `gcd(x, y)` is an integer combination of `x` and
  `y`, hence an integer multiple of `t`. Also `gcd(x + k y, y) = gcd(x, y)` for an integer `k`, because `x + k y, y`
  and `x, y` generate the same group.

Standard theorems used and not proved here (cited as `key:file:line` against `refs/`):

- (CRT) For pairwise coprime positive integers `q_1, ..., q_m` with product `H`, the map `Z/H -> product of Z/q_i`
  is a ring isomorphism. Source: `baker-padic:padicnotes.txt:374` (Theorem 1.20, stated for simultaneous
  congruences; its proof uses `Z/ab = Z/a x Z/b` for coprime `a, b`).
- (D) Every `z` in `Zhat` is congruent modulo `H Zhat` to an integer, for each positive integer `H`. Source:
  `Zhat = lim Z/N Z`, `tate-poonen:notes.txt:1603` (the class of `z` modulo `H` is its component in `Z/H Z`).

## 1. Hull, monotonicity, soundness of a policy

For balls `X = a + N Zhat`, `Y = b + M Zhat` let `T_+(X, Y) = (a + b) + gcd(N, M) Zhat` and
`T_*(X, Y) = a b + gcd(a M, b N, N M) Zhat` be the tight results of `SPEC.md` section 4.3. Radius 0 is allowed.

### Lemma 1 (the tight result is the smallest ball containing the result set).

Hypotheses: `X`, `Y` finite balls, radii `>= 0`, `op` one of `+`, `*`, `X op Y = {x op y : x in X, y in Y}`.
Claim: `X op Y` is inside `T_op(X, Y)`, and every ball `B` that contains `X op Y` contains `T_op(X, Y)`.

*Proof.*
1. For `+`: `X + Y = T_+(X, Y)` by `precision.md` Proposition 1. A ball containing `X + Y` contains `T_+`.
2. For `*`: containment is the enclosure part of `precision.md` Proposition 2.
3. Let `B = c + R Zhat` contain `X Y`, and `G = gcd(a M, b N, N M)`. If `G = 0`, `X Y = {a b}` (Proposition 2, case
   `G = 0`), so `T_* = {a b}` is inside `B`.
4. If `G > 0`: `B` contains the four products `a b`, `a b + a M`, `a b + b N`, `a b + a M + b N + N M` (the choices
   `u, v` in `{0, 1}` of Proposition 2). Since `a b` is in `B`, `B = a b + R Zhat`.
5. If `R = 0`, the four products are equal, so `a M = b N = N M = 0` and `G = 0`, excluded. So `R > 0`.
6. The differences `a M`, `b N`, `N M` (the last from the fourth product minus the second and third plus the first)
   lie in `R Zhat` and are rational, so `R` divides each of them (Lemma 1 of `precision.md`).
7. By (G2), `R | G`, so `G Zhat` is inside `R Zhat`, and `T_* = a b + G Zhat` is inside `a b + R Zhat = B`.

Check: `check_hull` (sampled rational points of `X op Y`; the gcd of all sampled differences is compared with the
radius of `T_op`, and every sample is tested for membership in `T_op`).
Used by: `SPEC.md` 4.3, 4.4.

### Lemma 2 (monotonicity).

Hypotheses: balls `X` inside `X'`, `Y` inside `Y'`; `op` in `{+, *}`. Claim: `T_op(X, Y)` is inside `T_op(X', Y')`.

*Proof.*
1. `X op Y` is inside `X' op Y'`, which is inside `T_op(X', Y')` (Lemma 1, first part).
2. So `T_op(X', Y')` is a ball containing `X op Y`; by Lemma 1 it contains `T_op(X, Y)`.

Check: `check_monotone`.
Used by: `SPEC.md` 4.4.

### Theorem 3 (every policy result contains the tight result, and the true value).

Hypotheses: a *policy* assigns to each operation `op` (sum, difference, product, sum with an exact scalar, product
with an exact scalar) and input balls `X, Y` a ball `P_op(X, Y)` with `T_op(X, Y)` inside `P_op(X, Y)` (for exact
scalars the scalar is a ball of radius 0), and may replace an input ball `X_j` by a ball containing it (a
conversion, as in Proposition 7). An expression is a finite tree whose leaves are true values `x_j` (finite adeles,
the same variable may occur several times) with given enclosing balls `X_j` containing `x_j`.

Claim: let `V_T` be the ball obtained by evaluating the tree with `T` at every node, `V_P` the ball obtained with
`P`, and `v` the true value. Then `v` is in `V_T` and `V_T` is inside `V_P`.

*Proof.* By induction on the tree.
1. Leaf: `v = x_j` is in `X_j = V_T`, which is inside `V_P`.
2. Node `e = e_1 op e_2` (difference: `e_1 + (-1) e_2`, and negation `-(a + N Zhat) = -a + N Zhat` is exact). By
   induction `v_i` is in `V_T(e_i)`, and `V_T(e_i)` is inside `V_P(e_i)`.
3. `v = v_1 op v_2` is in `V_T(e_1) op V_T(e_2)`, which is inside `T_op(V_T(e_1), V_T(e_2)) = V_T(e)` (Lemma 1).
4. By Lemma 2, `V_T(e)` is inside `T_op(V_P(e_1), V_P(e_2))`, which is inside `P_op(V_P(e_1), V_P(e_2)) = V_P(e)` by
   the hypothesis on `P`.

Repeated occurrences of a variable are harmless: each occurrence is enclosed. The theorem says nothing about
correlations (`x - x` gives a ball around 0).

The three policies of `SPEC.md` 4.4 satisfy the hypothesis: the tight policy trivially; the scaled policy by
Propositions 8 to 11 below and `precision.md` Propositions 5 and 6; the absolute cap by Proposition 14. So every
policy result contains the tight result.

Check: `check_expressions` (random expression trees, all three policies, a true value sampled in every leaf;
containment of the true value and of the tight ball is tested after every node).
Used by: `SPEC.md` 4.4; `PLAN.md` 1.7.

## 2. The scaled-residue policy

### Definition 4.

A context holds an integer `K >= 1`. A scaled value is `s (u + K Zhat)` with rational `s > 0` and integer
`0 <= u < K`; as a set it is the ball `s u + s K Zhat`. Exact rationals (including 0) keep their exact tag and are
not scaled values (a scaled value has radius `s K > 0`).

### Lemma 5 (the data are determined by the set).

Hypotheses: `K >= 1`; `s, s' > 0`; `0 <= u, u' < K`; `s (u + K Zhat) = s' (u' + K Zhat)`. Claim: `s = s'`, `u = u'`.

*Proof.*
1. By `precision.md` Proposition 3(1) the radii agree: `s K = s' K`, so `s = s'`.
2. Also `(s u - s u')/(s K) = (u - u')/K` is an integer; since `|u - u'| < K`, `u = u'`.

Check: `check_scaled_basics`.
Used by: `SPEC.md` 4.4 (canonical data of a scaled value).

### Lemma 6 (which balls are scaled values).

Hypotheses: `K >= 1`, a ball `c + R Zhat` with `R > 0`. Claim: it equals a scaled value of context `K` exactly when
`c K / R` is an integer; then `s = R/K` and `u = (c K / R) mod K`.

*Proof.*
1. If `c + R Zhat = s (u + K Zhat) = s u + s K Zhat`, then `R = s K` (Proposition 3(1)), so `s = R/K`, and by
   Proposition 3(1) `(c - s u)/(s K) = (c K/R - u)/K` is an integer. So `c K/R - u` is an integer multiple of `K`;
   as `u` is an integer, `c K/R` is an integer and `u = c K/R mod K`.
2. Conversely, with these `s, u`: `s K = R` and `(c - s u)/(s K) = (c K/R - u)/K`, an integer because
   `u = c K/R mod K`. By Proposition 3(1) the sets are equal.

Check: `check_scaled_basics`.
Used by: `SPEC.md` 4.4 (when conversion is exact).

### Proposition 7 (the best scaled enclosure of a ball).

Hypotheses: `K >= 1`, `X = c + R Zhat` with `R > 0`, `c` rational (zero allowed). Put `s* = gcd(c, R/K)` and
`u* = (c/s*) mod K`. Claim: `s* (u* + K Zhat)` contains `X`, and it is inside every scaled value of context `K` that
contains `X`.

*Proof.*
1. `s* > 0` because `R/K > 0`. Containment is `precision.md` Proposition 6(1).
2. Let `s (u + K Zhat)` contain `X`. By Proposition 3(3): `s K | R` and `s K | (c - s u)`.
3. From the second, `(c - s u)/s = c/s - u` is an integer multiple of `K`, so `c/s` is an integer: `s | c`.
4. From the first, `(R/K)/s` is an integer: `s | R/K`.
5. By (G2), `s | s*`; so `s K | s* K`.
6. Both balls contain `c`; `s* (u* + K Zhat) = c + s* K Zhat` (proof of Proposition 6(1)) and
   `s (u + K Zhat) = c + s K Zhat`. By Proposition 3(3) the first is inside the second.

Consequence: the loss of the conversion is the factor `R/(s* K)`; it is 1 exactly when Lemma 6 applies.

Check: `check_best_scaled` (all scales `n/m` with `n, m <= 12` and all residues are tried).
Used by: `SPEC.md` 4.4 ("conversion from a tight ball can lose precision and says so").

### Proposition 8 (addition of an exact scalar).

Hypotheses: `K >= 1`, `x = s (u + K Zhat)`, `q` an exact rational.

1. If `q = 0`, the result is `x` (exact).
2. If `q != 0`, put `g = gcd(s, q)` and `u' = (q/g + (s/g) u) mod K`. Then `x + q` is inside `g (u' + K Zhat)`, this
   is the best scaled enclosure of the tight result `(s u + q) + s K Zhat`, it equals the tight result exactly when
   `s | q`, and otherwise loses the factor `s/g`.

*Proof.*
1. The tight sum of `x` and the exact point `q` is `(s u + q) + s K Zhat` (Proposition 1 with radius 0 for `q`), and
   it equals `x + q` as a set.
2. Apply Proposition 7 with `c = s u + q`, `R = s K`: `s* = gcd(s u + q, s) = gcd(q, s) = g` by (G2), since `s u` is
   an integer multiple of `s`.
3. `s u + q` over `g` is `(s/g) u + q/g`, an integer; its residue is `u'`. So the enclosure of Proposition 7 is
   `g (u' + K Zhat)`, the best one.
4. The loss factor is `s K/(g K) = s/g`; it is 1 exactly when `g = s`, that is when `s | q`.

Example: `K = 3`, `x = 1 + 3 Zhat` (`s = 1`, `u = 1`), `q = 1/2`: `g = 1/2`, `u' = (1 + 2) mod 3 = 0`, result
`(1/2)(0 + 3 Zhat) = (3/2) Zhat`, which contains the tight `3/2 + 3 Zhat` and is coarser at 2. No scaled value of
context 3 equals `3/2 + 3 Zhat` (Lemma 6: `c K/R = 3/2`).

Check: `check_scalar_add`.
Used by: `SPEC.md` 4.4 ("exact scalars ... have their own rules").

### Proposition 9 (product with an exact scalar; recalled).

For an exact rational `q != 0`, `q s (u + K Zhat) = |q| s ((sign(q) u mod K) + K Zhat)`, exactly; for `q = 0` the
result is the exact 0. This is `precision.md` Proposition 6(2); the residue is reduced into `[0, K)` since
`(-u) + K Zhat = (K - u) + K Zhat`.

Check: `check_scalar_mul`.
Used by: `SPEC.md` 4.4.

### Proposition 10 (the product: the rule of the specification, and its tight variant).

Hypotheses: `x = s (u + K Zhat)`, `y = t (v + K Zhat)` in context `K`. Put `h = gcd(u, v, K)` (integer gcd; `h >= 1`
since `K >= 1`). Claim:

1. The tight product is `s t u v + s t K h Zhat`.
2. The rule of `SPEC.md` 4.4, `s t ((u v mod K) + K Zhat)`, contains it and loses the factor `h`.
3. The tight product is itself a scaled value of context `K`: it equals `(s t h) (((u v / h) mod K) + K Zhat)`.

*Proof.*
1. By Proposition 2 the tight radius is `gcd(s u t K, t v s K, s K t K) = s t K gcd(u, v, K)` by (G1), with centre
   `s t u v`.
2. `precision.md` Proposition 5(2). Its radius `s t K` divides `s t K h` with quotient `h`.
3. Lemma 6 with `c = s t u v`, `R = s t K h`: `c K/R = u v/h`, an integer because `h | u`. So `s = R/K = s t h` and
   the residue is `(u v / h) mod K`.

The specification's rule is therefore correct (an enclosure with loss factor `h`) but not tight. The tight variant
requires the integer gcd `h = gcd(u, v, K)`, the exact division of `u v` by `h`, and the scale update to `s t h`;
this is a word gcd only when `K` and its residues fit a machine word, which the context does not guarantee.
Example: `K = 4`, `x = y = 2 + 4 Zhat`: tight product `4 + 8 Zhat`; the rule gives `0 + 4 Zhat`; the variant gives
`2 (2 + 4 Zhat) = 4 + 8 Zhat`. With `u = v = 0` the rule loses the full factor `K`.

Check: `check_scaled_product`.
Used by: `SPEC.md` 4.4 (observation for the report; not an error of the specification).

### Proposition 11 (conversion between contexts).

Hypotheses: `K, K' >= 1`, `x = s (u + K Zhat)`. Put `s' = s gcd(u, K/K')` and `u' = (s u / s') mod K'`. Claim:

1. `s' (u' + K' Zhat)` contains `x` and is the best scaled enclosure of `x` in context `K'`.
2. It equals `x` exactly when `u K'/K` is an integer; in particular always when `K | K'`. Otherwise it loses the
   factor `K/(K' gcd(u, K/K'))`.

*Proof.*
1. Apply Proposition 7 to `c = s u`, `R = s K` and context `K'`: `s* = gcd(s u, s K/K') = s gcd(u, K/K')` by (G1).
   (For `u = 0`, `gcd(0, K/K') = K/K'`.) So `s* = s'` and `u* = u'`.
2. By Lemma 6, `x` is a scaled value of context `K'` exactly when `c K'/R = s u K'/(s K) = u K'/K` is an integer. If
   it is, Proposition 7's enclosure equals `x`, because it is inside every scaled value containing `x`, and `x`
   itself is one. If it is not, the enclosure is a scaled value of context `K'` and so differs from `x`.
3. If `K | K'` then `K'/K` is an integer and so is `u K'/K`.
4. The loss factor is `s K/(s' K') = K/(K' gcd(u, K/K'))`.

Example: `1 + 4 Zhat` to context 2 gives `1 + 2 Zhat` (loss 2); `1 + 2 Zhat` to context 4 gives `(1/2)(2 + 4 Zhat)`,
the same set.

Check: `check_conversion`.
Used by: `SPEC.md` 4.4 ("conversion between contexts ... have their own rules").

### Corollary 12 (operations across two contexts).

For `x` in context `K` and `y` in context `K'`, converting both to `L = lcm(K, K')` is exact (Proposition 11(2)).
The sum in context `L` is then the tight sum of `x` and `y` (`precision.md` Proposition 5(1)); the product by the
rule of the specification encloses the tight product, and the variant of Proposition 10(3) equals it. Converting to
`K`, `K'` or `gcd(K, K')` instead can lose precision (Proposition 11(2)).

Check: `check_conversion`.
Used by: `SPEC.md` 4.4.

## 3. The absolute cap

### Definition 13.

A cap is a rational `C > 0`. A capped value is a ball `c + R Zhat` with its own radius. After a tight operation with
result `c + R Zhat`, `R > 0`, the radius is replaced by `gcd(R, C)`.

### Proposition 14 (soundness; exact values).

Hypotheses: `C > 0`, a ball `c + R Zhat`, `R >= 0`. Claim:

1. `c + R Zhat` is inside `c + gcd(R, C) Zhat`.
2. For `R = 0` (an exact result of exact inputs) the cap is not applied: the exact value keeps its tag. This is
   required by `SPEC.md` 4.1 (`docs/SPEC.md:114`): the exact rational "stays exact under arithmetic with other exact
   values". The literal formula `gcd(0, C) = C` would give `c + C Zhat`, which contains `c` and so is an enclosure,
   but it breaks that requirement. The cap acts on every result of positive radius, including the product of an
   exact scalar with a ball.
3. `gcd(R, C)` is the finest radius `R'` with `R' | R` and `R' | C`: the cap is the best enclosure among balls whose
   radius is nowhere finer than `C`.

*Proof.*
1. `gcd(R, C) | R` (the generator divides each generator of the group, R being one of them); if `R = 0`,
   `gcd(0, C) = C`. Apply Proposition 3(3) (both balls contain `c`).
2. The exact result is its own tight result; the literal formula gives a ball containing it by item 1.
3. If `R' | R` and `R' | C` then `R' | gcd(R, C)` by (G2).

The specification says only "after a tight operation"; with the requirement of `SPEC.md` 4.1 the reading of item 2
is the only compliant one. A clarifying sentence in `SPEC.md` 4.4 is proposed in the review (R8).

Check: `check_cap`.
Used by: `SPEC.md` 4.4 (item 3).

### Proposition 15 (the invariant of capped values).

Hypotheses: `C > 0`; every capped value of positive radius was produced by Definition 13. Claim:

1. Every capped radius `R > 0` satisfies `R | C`, that is `v_p(R) <= v_p(C)` for every prime `p`.
2. The cap is idempotent, and `gcd(R, C) = R` exactly when `R | C`.
3. The sum of two capped values needs no capping: `gcd(R_1, R_2) | C` when `R_1 | C` and `R_2 | C`.
4. Products and products with exact scalars can produce radii with `R` not dividing `C`; there the cap acts.

*Proof.*
1. `gcd(R, C) | C` as in Proposition 14.1.
2. `gcd(gcd(R, C), C) = gcd(R, C)` because both generate the same group. If `R | C`, the group generated by `R, C`
   is `R Z`, so `gcd(R, C) = R`; conversely `gcd(R, C) | C`.
3. `gcd(R_1, R_2)` divides `R_1`, which divides `C`.
4. Example: `C = 1`, `(0 + 1 Zhat) * (0 + 1 Zhat)` has tight radius `gcd(0, 0, 1) = 1`; but `2 * (0 + 1 Zhat)` has
   tight radius 2, capped to 1.

Check: `check_cap`.
Used by: `SPEC.md` 4.4.

## 4. The local backend

### Definition 16.

A *block context* is a list of pairwise coprime integers `q_1, ..., q_m >= 1` with product `H`. A *local value* in
this context is `(d; r_1, ..., r_m)` with an integer `d >= 1` and integers `0 <= r_i < q_i`. Its set is
`(A + H Zhat)/d` for any integer `A` with `A = r_i mod q_i` for all `i`. The global form of the same set is the
triple `(A, H, d)`. Exact values (`H = 0`) are never local values.

### Lemma 17 (the local value is well defined, and is the same set as the global form).

Hypotheses: as in Definition 16. Claim:

1. An integer `A` as required exists and is unique modulo `H`; the set `(A + H Zhat)/d` does not depend on its
   choice. So the local value and the global form `(A mod H, H, d)` represent the same set.
2. In a fixed context, distinct data `(d; r)` give distinct sets.
3. Conversion from local to global is recombination by CRT; no division is involved.

*Proof.*
1. By (CRT), `A` exists and is unique modulo `H`. If `A' = A + H k` then `A' + H Zhat = A + H Zhat`, so the set is
   the same.
2. The set `(A + H Zhat)/d = A/d + (H/d) Zhat` determines its radius `H/d` (Proposition 3(1)), hence `d`; and its
   centre modulo `H/d`, hence `A` modulo `H`, hence every `r_i`.
3. Immediate from 1.

Check: `check_local_repr`.
Used by: `SPEC.md` 4.1 (two backends for the same value).

### Lemma 18 (the canonical cancellation is computed blockwise).

Hypotheses: as in Definition 16. Claim: `gcd(A, H) = product of gcd(r_i, q_i)`, and
`gcd(A, H, d) = gcd(product of gcd(r_i, q_i), d)`.

*Proof.*
1. `gcd(r_i, q_i) = gcd(A, q_i)` because `A = r_i + q_i k`.
2. The `gcd(A, q_i)` are pairwise coprime divisors of `A` (each divides `q_i`), so their product divides `A` and
   `H`.
3. Conversely let `e = gcd(A, H)`; for each prime power `p^f` exactly dividing `e`, `p` divides exactly one `q_i`
   and `p^f` divides `gcd(A, q_i)`. So `e` divides the product. Both divide each other and are positive.
4. The second statement follows because `gcd(A, H, d) = gcd(gcd(A, H), d)`.

Check: `check_local_repr`.
Used by: `SPEC.md` 4.1 (canonical form without recombination).

### Proposition 19 (which balls live in a context).

Hypotheses: a block context with product `H`; a ball `c + R Zhat`, `R > 0`, `c` rational. Claim: it is the set of a
local value of this context exactly when `H/R` and `c H/R` are integers; the value is then unique, with `d = H/R`
and `r_i = (c H/R) mod q_i`.

*Proof.*
1. If `(A + H Zhat)/d = c + R Zhat`, then `H/d = R` (Proposition 3(1)), so `d = H/R` is an integer, and
   `(c - A/d)/R = (c d - A)/H` is an integer. So `c d - A` is in `H Z`, and `c d = c H/R` is an integer.
2. Conversely, put `d = H/R`, `A = c d`; then `(A + H Zhat)/d = c + R Zhat`. Uniqueness is Lemma 17.2.

Check: `check_local_ops`.
Used by: `SPEC.md` 4.1 ("the result then falls back to the global backend or is given a new context").

### Proposition 20 (conversion of a global ball into a context: best enclosure).

Hypotheses: block context with product `H`; `X = c + R Zhat`, `R > 0`, `c` a rational point of `X`. Write
`H/R = n/m` in lowest terms and let `e` be the denominator of `c`. Put `d0 = lcm(n, e)` and `A0 = c d0`. Claim: `d0`
does not depend on the choice of `c` in `X ∩ Q` (although `e` may: `1/2 + (1/2) Zhat` contains `1/2` and `1`);
`(A0 + H Zhat)/d0` contains `X`; it is inside every local value of the context that contains `X`; it equals `X`
exactly when `d0 = H/R`.

*Proof.*
1. A local value `(A + H Zhat)/d` contains `X` exactly when (Proposition 3(3)) `(H/d) | R` and `(H/d) | (c - A/d)`.
2. The first condition: `R d/H = m d/n` is an integer, that is `n | d` (as `gcd(m, n) = 1`).
3. The second: `(c d - A)/H` is an integer. It forces `c d` to be an integer, that is `e | d`; conversely if `c d`
   is an integer, `A = c d` satisfies it.
4. The rational points of `X` are `c + R k`, `k` in `Z` (`precision.md` Lemma 1). Replacing `c` by `c + R k` changes
   `c d` by `R k d = H k (m d/n)`, an integer when `n | d`. So the set of admissible `d` (those with `n | d` and
   `c d` an integer) does not depend on the choice of `c`.
5. The admissible `d` are exactly the positive multiples of `lcm(n, e)`. Since this set does not depend on `c` (step
   4), neither does its least element `d0`.

### Proposition 21 (negation and sum at a shared context are blockwise and stay in the context).

3. The result is in canonical form exactly when `gcd(A L/d + B L/e, H, L) = 1`; otherwise canonical cancellation

### Proposition 22 (product at a shared context).

Hypotheses: `x = (d; r_i)`, `y = (e; s_i)` in the same block context, global numerators `A`, `B`. Put
`h_i = gcd(r_i, s_i, q_i)` and `h = product of h_i`. Claim:

1. `h = gcd(A, B, H)`, and the tight product is `(A B + H h Zhat)/(d e)`.
2. The blockwise product `(d e; r_i s_i mod q_i)` contains the tight product and loses the factor `h`; it is tight
   exactly when `h = 1`, that is when `gcd(r_i, s_i, q_i) = 1` for every block.
3. The tight product is a local value of the same context exactly when `h | d e`; it is then
   `(d e/h; (A B/h) mod q_i)`, and blockwise `(A B/h) mod q_i = ((r_i s_i mod q_i h_i)/h_i) w'_i mod q_i`, where
   `w'_i` is the inverse of `h/h_i` modulo `q_i` (it exists: `h/h_i` is a product of divisors of the other blocks).
4. In every case the tight product is the local value `(d e; r_i s_i mod q_i h_i)` of the derived context with
   blocks `q_i h_i` (pairwise coprime, product `H h`). No factorisation and no inversion is needed.

*Proof.*
1. As in Lemma 18, `gcd(A, B, H) = product of gcd(A, B, q_i) = product of gcd(r_i, s_i, q_i)`. By Proposition 2 with
   `a = A/d`, `N = H/d`, `b = B/e`, `M = H/e` the tight radius is `gcd(A H, B H, H H)/(d e)` by (G1), which is
   `H gcd(A, B, H)/(d e) = H h/(d e)`; the centre is `A B/(d e)`.
2. The blockwise product is the set `(A B + H Zhat)/(d e)` (reduction modulo `q_i` is a ring homomorphism; Lemma
   17). Its radius `H/(d e)` divides `H h/(d e)` with quotient `h`; both contain `A B/(d e)`; Proposition 3(3).
3. Proposition 19 with `R = H h/(d e)`, `c = A B/(d e)`: `H/R = d e/h` and `c H/R = A B/h`; the second is an integer
   since `h | A`. So the condition is `h | d e`. For the blockwise formula: by step 4 below, `A B = r_i s_i` modulo
   `q_i h_i`, and `h_i` divides both sides, so `A B/h_i = (r_i s_i mod q_i h_i)/h_i` modulo `q_i`; then
   `A B/h = (A B/h_i)/(h/h_i)`, and `h/h_i` is invertible modulo `q_i`.
4. `h_i | q_i`, so `q_i h_i` has the same primes as `q_i`; the blocks stay pairwise coprime, product `H h`. The
   residue `A B mod q_i h_i` is `r_i s_i mod q_i h_i`: with `A = r_i + q_i k`, `B = s_i + q_i l`,
   `A B - r_i s_i = q_i (k s_i + l r_i) + q_i^2 k l`, and `h_i` divides `s_i`, `r_i` and `q_i`. It does not depend
   on the choice of `A`, `B` modulo `H` for the same reason.

Example: blocks `(4)`, `x = y = 2 + 4 Zhat` (`d = e = 1`, `r = s = 2`): `h = 2`; blockwise `0 + 4 Zhat`; tight
`4 + 8 Zhat`, not in the context (`h` does not divide `d e = 1`), and in the derived context `(8)` it is
`(1; 4 mod 8)`.

Used by: `SPEC.md` 4.1 ("a tight operation ... can change `H` and `d`").

### Proposition 24 (canonical cancellation: the set stays in the context, the canonical triple does not).

Hypotheses: `x = (d; r_i)` in a block context with product `H`; `A` the lift with `0 <= A < H`; `g = gcd(A, H, d)`
(computed by Lemma 18) with `g > 1`; `g_i = gcd(g, q_i)`. Claim:

1. The set of `x` is the set of the triple `(A/g, H/g, d/g)`, and this triple is canonical in the sense of `SPEC.md`
   4.1: `0 <= A/g < H/g` and `gcd(A/g, H/g, d/g) = 1`.
2. The set is a local value of the original context, namely `x` itself; Proposition 19 holds for it with `H/R = d`
   and `c H/R = A`. Cancellation does not force the *set* out of the context.
3. The canonical *triple* is not the data of any local value of the original context: its numerator modulus is
   `H/g != H`. It is the local value `(d/g; (r_i/g_i) w_i mod (q_i/g_i))` of the derived context with blocks
   `q_i/g_i`, where `w_i` is the inverse of `g/g_i` modulo `q_i/g_i`. That inverse exists because `g/g_i` is coprime
   to `q_i`. A block reduced to 1 carries the residue 0 and can be dropped.
4. Consequence for storage: a backend that keeps raw data may leave `x` as it is (same set, same context); a backend
   whose invariant is canonical data, as the struct comment `docs/PLAN.md:60` requires
   (`H > 0: 0 <= A < H, gcd(A,H,d) = 1`), must move to the derived context of item 3 or to the global backend.
   Either way, equality and printing must use the canonical triple (or compare sets), never the raw data.

*Proof.*
1. `(A + H Zhat)/d = (g (A/g) + g (H/g) Zhat)/(g (d/g)) = (A/g + (H/g) Zhat)/(d/g)`. From `0 <= A < H` and `g | A`,
   `g | H`: `0 <= A/g < H/g`. And `gcd(A/g, H/g, d/g) = gcd(A, H, d)/g = 1`.
2. `x` is a local value of the context by definition, and its set is the set of item 1. For Proposition 19: the
   radius is `R = H/d`, so `H/R = d` and `c H/R = (A/d) d = A`, both integers.
3. `g | H`, and `g = product of g_i` since the `q_i` are pairwise coprime (as in Lemma 18). So `g/g_i` is a product
   of divisors of the other blocks, coprime to `q_i`, and invertible modulo `q_i/g_i`. The blocks `q_i/g_i` are
   pairwise coprime with product `H/g`. `g_i` divides `A` and `q_i`, hence it divides `r_i = A - q_i k`. Write
   `A = g A'`. Then `(g/g_i) A' = A/g_i = r_i/g_i` modulo `q_i/g_i`, so `A' = (r_i/g_i) w_i` modulo `q_i/g_i`.
4. Items 1 to 3.

Example (from the review): blocks `(4)`, `(d; r) = (2; 2)`, `A = 2`, `g = 2`. The set is
`(2 + 4 Zhat)/2 = 1 + 2 Zhat`; it is the local value `(2; 2)` of the context `(4)`, and its canonical triple
`(1, 2, 1)` lives in the derived context `(2)` as `(1; 1)`.

Check: `check_local_ops` (derived context), `check_backend_repairs` (item 2, by a search over all `(d', A')` of the
original context).

### Proposition 25 (the denominator and a block with a common factor).

Hypotheses: a local value `(d; r_i)` in a block context with product `H`, numerator `A` (any lift), a block
`q = q_i`, `g = gcd(d, q)`. Claim:

1. `d` is invertible modulo `q` exactly when `g = 1`. The congruence `d x = A` modulo `q` has a solution exactly
   when `g | A`, and then exactly `g` solutions modulo `q`.
2. If `g = 1`, every element of the ball `(A + H Zhat)/d` lies in `Z_p` for each prime `p | q`, and all its elements
   are congruent modulo `q` to `A d*`, `d*` the inverse of `d` modulo `q`. If `g > 1`, the ball determines no
   residue modulo `q`: for a prime `p | g`, `v_p(H/d) < v_p(q)`, so the elements `A/d` and `A/d + H/d` differ by an
   element of `p`-valuation below `v_p(q)`.
3. A solution of `d x = A` modulo `q` computed from one lift `A` is therefore not a property of the value when
   `g > 1`: the lifts `A = 2` and `A = 6` of the residue 2 modulo `H = q = 4`, with `d = 2`, have centres 1 and 3,
   both in the ball `1 + 2 Zhat`, and `2 x = 2` modulo 4 has the two solutions 1 and 3.
4. In Lemma 17 and Propositions 20 to 24 the denominators `d, e, L, n` are only multiplied, or divided exactly, as
   integers outside the residues. The only modular inversions there are of `h/h_i` modulo `q_i` (Proposition 22.3)
   and of `g/g_i` modulo `q_i/g_i` (Proposition 24); in both cases the two numbers are coprime.

*Proof.*
1. If `g = 1`, Bezout gives `d*`. If `g > 1` and `d x - 1 = q y`, then `g | 1`, impossible. If `d x - A = q y`, then
   `g | A`. Conversely write `A = g A'`, `d = g d'`, `q = g q'` with `gcd(d', q') = 1`; `d x = A` modulo `q` is
   equivalent to `d' x = A'` modulo `q'`, which has exactly one solution modulo `q'`, that is `g` solutions modulo
   `q`.
2. `v_p(H) = v_p(q)` for `p | q`, as the other blocks are coprime to `q`. If `g = 1`, `d` is a unit of `Z_p` for
   `p | q`, so `A/d` is in `Z_p` and `H/d` is in `q Z_p`; and `A/d - A d* = A (1 - d d*)/d` is in `q Z_p`. So every
   element of the ball is `A d*` modulo `q Z_p` at each `p | q`, which is congruence modulo `q` (S2 of `ideles.md`).
   If `g > 1`, take `p | g`: `v_p(H/d) = v_p(q) - v_p(d) <= v_p(q) - 1`.
3. `2/2 = 1`, `6/2 = 3`, and `(3 - 1)/2 = 1` is an integer, so both lie in `1 + 2 Zhat` (Lemma 1 of `precision.md`);
   `2 * 1 = 2 * 3 = 2` modulo 4.
4. By inspection of the proofs cited; the coprimality of `h/h_i` and `q_i` is shown in Proposition 22, that of
   `g/g_i` and `q_i/g_i` in Proposition 24.

Rules for the C code of the local backend (`PLAN.md` 1.8), from Propositions 21 to 25:

- Store the residues of the integer numerator `A` modulo each block and the denominator `d` once per value
  (Definition 16). Apply `d` only after recombination, as the denominator of `(A + H Zhat)/d`.
- Compute modular inverses only of integers coprime to the modulus: `h/h_i` modulo `q_i`, `g/g_i` modulo `q_i/g_i`,
  and `d` modulo `q_i` only when `gcd(d, q_i) = 1` (for example to print the residue that item 2 shows the ball
  determines).
- Never compute an inverse of `d` modulo a block with `gcd(d, q_i) > 1`; never replace a numerator residue by a
  solution of `d x = A` modulo `q_i`; never report such a solution as a residue of the value (items 1 to 3).
- Compare and print values through their canonical triples (Proposition 24.4), not through raw residues.

the example of item 3), `check_local_ops`.

### Summary 26 (raw representation and canonical form).

In a block context with product `H` (the context fixes `H`; `d` belongs to the value). "Raw" is the representation
produced by the operation before canonical cancellation; "canonical" is the triple of `SPEC.md` 4.1. Inputs are
`x = (A + H Zhat)/d`, `y = (B + H Zhat)/e`, `L = lcm(d, e)`, `h = gcd(A, B, H)`.

| Operation | raw result | canonical numerator modulus |
|---|---|---|
| negation | `d`, `H` unchanged (P21) | unchanged, as `gcd(-A mod H, H, d) = gcd(A, H, d)` |
| sum | denominator `L`, `H` unchanged (P21) | `H/g_s`, `g_s = gcd(A L/d + B L/e, H, L)` |
| product, blockwise | denominator `d e`, `H` unchanged; an enclosure losing `h` (P22.2) | not the tight set |
| product, tight | `(d e/h; A B/h)` if `h` divides `d e`; else blocks `q_i h_i` (P22) | `H h/gcd(A B, H h, d e)` |
| scalar `m/n` | `(n d/abs(m); sign(m) A)` if `abs(m)` divides `d`; else new `H` | `abs(m)H/gcd(mA, abs(m)H, nd)` |
| cancellation by `g > 1` | set unchanged, still in the context (P24.2) | `H/g`, derived blocks `q_i/g_i` (P24.3) |
| conversion of a global ball | Proposition 20 | as for the set |

So the raw representation keeps `H` for negation, sum and blockwise product, but the canonical form can change `H`
after any of them. Examples: `(1 + 2 Zhat)/2 + (1 + 2 Zhat)/2` has raw form `(2 + 2 Zhat)/2` and canonical form
`(0 + 1 Zhat)/1`, so `H` goes from 2 to 1; the tight product of `(1 + 6 Zhat)/2` and `(2 + 6 Zhat)/3` has `h = 1`,
raw form `(2 + 6 Zhat)/6`, canonical form `(1 + 3 Zhat)/3`. A canonical triple may need a new context although its
set is still representable in the old one (P24). Every derived context is computed without factorisation. A block of
a derived context that no longer fits a machine word forces the global backend (`SPEC.md` 4.1).

*Proof of the canonical column.* For a raw triple `(A', H', d')` with `H' > 0`, first put
`R = A' mod H'` in `0 <= R < H'`. Set `g' = gcd(R, H', d') = gcd(A', H', d')`. The canonical triple is
`(R/g', H'/g', d'/g')`. The canonical numerator modulus is therefore `H'/g'`, as displayed in the table. The raw
triples are those of Propositions 21 to 23; for the tight product the raw triple is `(A B, H h, d e)`
(Proposition 22.1), for the scalar `(m A, abs(m) H, n d)` (Proposition 23.1), and the gcd does not depend on the
lift of the numerator because the modulus is among its arguments.

Check: `check_backend_repairs` (canonical moduli against an independent canonicalisation of the set; the two
examples), `check_s26_centre` (the modulo-`H'` reduction, with the `(9, 4, 1)` witness).
