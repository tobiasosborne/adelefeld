# adelefeld: the public C interface of milestone 1

Version 0.1.0 of `include/adelefeld.h`, written by the lane `m1-headers` on 2026-09-28 against
`docs/conventions.md` 0.4, `docs/SPEC.md` 1.3 and `docs/PLAN.md` 1.3 (with the closure edits E1 to E4 and C1 to C5
of `docs/reviews/m0-gate/closure.md`). Declarations only: no function is implemented yet. The contract of each
function is the comment block above its declaration; this file lists the functions and where each one comes from.

## Choices

Where the conventions leave a signature or a status undetermined, or contradict each other, the headers make the
choice below. The report of the lane `m1-headers` lists the same cases as findings.

1. **Name of the point comparison.** Conventions 2.1 fixes its values, not its name. Chosen:
   `adf_fball_compare(x, y)`, as the reference `tests/ref/adfref/fball.py` names it.
2. **`adf_fball_prec_at` for an exact ball or the archimedean place.** Not covered by conventions. Chosen:
   `ADF_DOMAIN`, `*e` untouched (the precision of a point is infinite and no `slong` holds it).
3. **Negative denominator in `adf_fball_set_fmpz3`.** Conventions 4.4 names only the zero denominator. Chosen:
   accepted and normalised, `(A + H Zhat)/d = (-A + H Zhat)/(-d)`, as `canon` in the reference does.
4. **Scaled operations that cannot fail.** Conventions 3.2 lists neg and scaling among the scaled operations with
   `OK, DOMAIN`, while 2.3 says that a function that cannot fail returns `void`. Chosen: `adf_scaled_neg`,
   `adf_scaled_mul_rat`, `adf_scaled_add_rat` return `void` (they have one scaled input, so no pointer check). The
   conversions `adf_scaled_set_fball` and `adf_scaled_set_context` return `int`, always `ADF_OK`: closure C5 gives
   the second with `int`, against 2.3; the first follows it.
5. **Capped operations.** Conventions 3.2 has no row. Chosen: `int`, `ADF_DOMAIN` when the cap `C <= 0`.
6. **`adf_fball_set_local_enclose`.** Named in conventions 5.3, no status row. Chosen: `ADF_DOMAIN` for an exact
   input (no local value is a point), `ADF_UNSUPPORTED` for a context without blocks.
7. **Context families.** `adf_modctx_new_factorial` when a prime-power block of `n!` reaches `2^64`: chosen
   `ADF_UNSUPPORTED` (as `adf_modctx_new_prime_powers`), not a context without blocks; such a modulus remains
   available to the scaled policy through `adf_modctx_new_fmpz`. "Powers of a primorial" has no name or
   signature in the conventions: chosen `adf_modctx_new_primorial_pow(out, n, e)`, modulus the `e`-th power of
   the product of the primes `p <= n`. `k = 0` blocks in `adf_modctx_new_blocks` and `_prime_powers` gives
   `K = 1` without blocks; an exponent 0 in `_prime_powers` is `ADF_DOMAIN`.
8. **Binding arrays.** Conventions 8.1 writes `const adf_modctx_struct ** binds`. In C an array of
   `const adf_modctx_struct *` then needs no cast, but `adf_modctx_struct **` cannot be passed. Chosen:
   `const adf_modctx_struct * const * binds`, which the loader only reads.
9. **Loaders of types without contexts.** Conventions 8.1 gives one template for every type. Chosen: `adf_rat`
   keeps the `ctx` argument (ignored, NULL allowed), `_load_str_binds` (only `nbinds = 0` matches) and
   `_dump_inspect` (always 0 occurrences), so that every type has the same four functions.
10. **`_t` names of plain structs.** `adf_text_limits_t`, `adf_ctx_desc_t` and `adf_place_t` are plain structs,
    while conventions 1 and 2.1 reserve `_t` for arrays of one struct. Kept as conventions 7, 8.4 and 10.2 write
    them.
11. **`ADF_INLINE`.** Conventions 12.1 defines it as `static __inline__` (FLINT's spelling, a GNU extension), and
    the foreign-function rules forbid compiler extensions. Chosen: `static inline` (C99, C++).
12. **Status names.** `adf_status_str` returns the name without `ADF_` (as the golden files write statuses) and
    `"UNKNOWN"` for a value outside 0 to 10; conventions fix neither.
13. **Additions not named in the conventions**, all in the pattern of conventions 2: `adf_rat_zero`, `_one`,
    `_set_si`, `_set_fmpz`, `_set_fmpz2`, `_set_fmpq`, `_get_fmpq`, `_is_zero`, `_equal`, `_sgn`, `_inv`;
    `adf_fball_zero`, `_one`, `_set_si`, `_set_fmpz`, `_set_rat`, `_set_center_radius`, `_is_exact`,
    `_get_fmpz3`, `_is_local`, `_context`; `adf_adele_set_si`, `_add_rat`, `_get_real`, `_get_arb_at`,
    `_get_fin`; `adf_cadele_set_adele`, `_get_complex`, `_get_fin`, `_add_rat`; `adf_modctx_get_modulus`,
    `_nblocks`, `_block`, `_dump_str`, `_matches_desc`; `adf_scaled_context`, `_is_exact`, `_set_rat`,
    `_get_fball`, `_get_str`; `adf_text_limits_default`; `adf_alignof_*`.
14. **Reconstruction with several candidates** returns `ADF_NOT_UNIQUE` with the output untouched; there is no
    function that lists the candidates (SPEC 9.2 does not ask for one).
15. **One header or several.** `docs/PLAN.md` section 2 says "the public interface (one header)"; the brief asks
    for `include/adelefeld/*.h`. `include/adelefeld.h` includes them all, so a user still includes one header.
