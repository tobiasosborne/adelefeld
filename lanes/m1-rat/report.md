# Lane m1-rat: report

Work package 1.2 of `docs/PLAN.md` (the part for `adf_rat`), together with the status strings and
the places of conventions 7. Lane directory: `lanes/m1-rat`. Date: 2026-09-28.

## What was done

Every function that `include/adelefeld/status.h`, `include/adelefeld/place.h` and
`include/adelefeld/rat.h` declare is implemented and is a defined symbol of the library: 33
functions, 1 from `status.h`, 8 from `place.h`, 24 from `rat.h`.

- `adf_rat` (24 functions): one canonical `fmpq` per value (conventions 5.1). The life cycle, the
  constructors from raw data with their `ADF_DOMAIN` for a zero denominator, the predicates, and
  the exact ring arithmetic. The only two statuses a function of this type returns are `ADF_DOMAIN`
  (raw data that break the invariant) and `ADF_NOT_UNIT` (a divisor or an operand of an inversion
  that is the exact 0), and every check is made before any write, so the output is untouched on
  every status other than `ADF_OK` (conventions 4.3).
- `adf_place` (6 functions plus the two layout queries): an 8-byte opaque handle whose word is 0
  for the archimedean place and the prime `p` for a finite place. `adf_place_prime` certifies
  primality with `n_is_prime` and returns `ADF_DOMAIN` without writing when `p` is 0, 1 or
  composite (conventions 4.4, "composite p ... ADF_DOMAIN from constructors"). The canonical order
  of conventions 7 (the archimedean place first, then the primes in increasing order) is the
  numeric order of the stored words, because a prime is at least 2.
- `adf_status_str` is a header-inline function, so `src/inlines.c` (which defines `ADF_INLINES_C`
  before including `<adelefeld.h>`) compiles it with external linkage. The same file exports the
  inline functions of the other headers too: 46 `adf_` symbols in the shared object, of which 33
  belong to the three headers of this lane.
- `src/status.c` holds the compile-time check of the fourteen constants of `status.h` against
  conventions 3.1 and 2.1. There is no other operation of `status.h` to put in a source file.

## The oracles and the vectors

`tests/ref/vectors/*.jsonl` (of the reference `tests/ref/adfref/`) has no file for the exact
rationals: its `scale.jsonl` carries a rational `q` as the scalar of a ball, which is work package
1.2 of the `adf_fball` lane, not of this one. `tests/ref/adfref/rat.py` holds `qgcd`, `qlcm`,
`is_integer` and `v_p`, none of which is an operation of `adf_rat`. So the vectors of this lane
are generated by `lanes/m1-rat/gen_rat_vectors.py` from `fractions.Fraction` of the standard
library (the exact rational arithmetic of GMP, in the same canonical form as conventions 5.1),
the way `tests/ref/adfref/fball.py` uses `Fraction` for rational centres. The generator asserts
`gcd(num, den) = 1` and `den > 0` for every value it writes, so no vector records a non-canonical
pair, and it is deterministic: two runs give byte-identical files (md5 of `rat_add.jsonl`:
`0ab0e0eebec80299c7ce5f324e2df418` on both runs).

The files, their records and what they cover:

| File | Records | Operations |
|---|---|---|
| `rat_set.jsonl` | 448 | `set_fmpz2` and `set_fmpq` from raw pairs, including a zero denominator (`DOMAIN`) |
| `rat_set_si.jsonl` | 128 | `set_si`, `n` up to `2^62` and down to `-2^62` |
| `rat_add.jsonl`, `rat_sub.jsonl`, `rat_mul.jsonl` | 471 each | the three operations |
| `rat_neg.jsonl` | 244 | `neg` |

| `rat_inv.jsonl` | 211 | `inv`, including the inverse of the exact 0 (`NOT_UNIT`) |

| `rat_is_zero.jsonl`, `rat_sgn.jsonl` | 211 each | `is_zero`, `sgn` |

`tests/test_rat.c` runs every record of every file; no file is read partially. Each binary
operation is run four times per record: with a third object as the output, with the first input as
the output, with the second input as the output, and with one object as all three (`(x, x, x)`),
which is the aliasing list of conventions 4.1 and of `docs/PLAN.md` section 7. On the refused path
of `adf_rat_div` and `adf_rat_inv` the same three aliasings are run and the output is compared
with its value from before the call.

## What the tests cover beyond the vectors

- the life cycle: `init` gives 0/1, `clear`, `set` into itself, `swap` twice, `get_fmpq`;
- the exact zero and the exact one, and the canonical form of the zero after `+`, `-`, `*`, `neg`,
  `div` and `inv` (the exact zero survives every one of them);
- `DOMAIN` for a zero denominator through both constructors, and `NOT_UNIT` for the exact 0 in
  `div` and `inv`, each with the claim that the output is bitwise what it was (the sentinel 7/3,
  which is neither 0 nor 1, or the input value itself when the output is an input);
- the predicate `adf_rat_is_canonical` on a value that is 8/2, on one with a negative denominator
  and on one with a zero denominator;
- a copy owns its own limbs: writing through one value leaves the other alone;
- huge operands: 3^1024 (494 digits) through ten squarings, `x / x` for it, and the exact values
  1/3 + 1/7 = 10/21, 1/3 * 1/7 = 1/21, (1/21) / (1/7) = 1/3, 1/(1/3) = 3;
- the places: 9 primes including 18446744073709551557 = 2^64 - 59, 15 words that are not prime
  including 0, 1, 2^63, 2^64 - 1 and 2^64 - 2; the output untouched on `DOMAIN`; the canonical
  order against a list of 8 places with antisymmetry, reflexivity and transitivity; the layout
  queries, 8 and 8;
- the statuses: the eleven values, the three comparison values, the eleven names, that the names
  are pairwise distinct and carry no `ADF_` prefix, `"UNKNOWN"` outside 0 to 10 including
  `INT_MIN` and `INT_MAX`, and that the string of a code is the same pointer at every call.

## Performance notes (COMMON-C rule 7)

The code is the simple version; no optimisation was attempted. Three avoidable costs:

1. `adf_rat_inv` initialises and clears a local `fmpq` holding the exact 1, because `fmpq_inv`
   documents no aliasing rule. The value 1 is two small `fmpz`, so the init allocates nothing and
   the clear frees nothing; a direct `1/x` would swap the two fields and move the sign, and would
   need a temporary of its own for the aliased case. Not worth the risk of relying on wording
   FLINT does not state.
2. `adf_rat_set_fmpq` copies both fields and then canonicalises, so the gcd runs on the copy. A
   version that canonicalises into a temporary and swaps would allocate; the current one does not.
3. `adf_place_cmp` is a comparison of two words, and `adf_place_prime` is one `n_is_prime` on a
   word, which for a large prime is a Miller-Rabin test. Nothing to avoid.

## Findings

### Findings against the specification

None. Nothing in `docs/SPEC.md` 4.1, in the conventions or in the three headers contradicts what
was implemented, and no counterexample was found.

### Findings against the conventions and the plan (not errors, but gaps the orchestrator should see)

1. **`-DADF_CHECK_INVARIANTS` is not implemented.** Conventions 4.4 (DECISION CV-09) says: "With
   `-DADF_CHECK_INVARIANTS` every public function checks `adf_x_is_canonical` on entry and calls
   `flint_abort` with a message", and `include/adelefeld/modctx.h:19` already promises it for
   contexts. No header of this lane mentions the flag, and the Makefile has no target that builds
   with it. I wrote the check, measured it, and removed it: the code sits inside `#ifdef`, so the
   mutation run of the default build cannot see it and three mutants of `src/rat.c` survived
   (`make mutate FILES=src/rat.c` failed), and `tools/mutate/equivalent.txt` is not mine and takes
   only equivalent mutants. A per-type private copy would also be a second mechanism beside the one
   the context lane needs. The check belongs in one place for every type, together with a Makefile
   target, so that one run tests it. The code is short and is in this report so that the owner of
   the shared build can add it:

   ```c
   #ifdef ADF_CHECK_INVARIANTS
   static void
   adf_rat_check_canonical(const adf_rat_t x, const char * who)
   {
       if (!fmpq_is_canonical(x->q))
       {
           flint_printf("adelefeld: %s: the input is not a canonical adf_rat"
                        " (den > 0 and gcd(num, den) = 1, conventions 5.1)\n", who);
           flint_abort();
       }
   }
   #define ADF_RAT_CHECK(x, who) adf_rat_check_canonical(x, who)
   #else
   #define ADF_RAT_CHECK(x, who) ((void) 0)
   #endif
   ```

   called at the head of `adf_rat_set`, `_swap`, `_identical`, `_get_fmpq`, `_is_zero`, `_equal`,
   `_sgn`, `_add`, `_sub`, `_mul`, `_neg`, `_div` and `_inv`. With it,
   `sh lanes/m1-rat/check_invariants.sh` reports 14 of 14 aborting; without it, 0 of 14.

2. **Two different kinds of "comparison" return `int`.** `adf_place_cmp` returns -1, 0 or 1 in the
   canonical order of places (conventions 7), while the comparison of two *points* returns the
   three `ADF_CMP_*` values (conventions 2.1, closure finding C1) and the three values coincide
   with `ADF_OK`, `ADF_NOT_DETERMINED` and `ADF_UNIT_NOT_CERTIFIED`. Nothing in the interface stops
   a caller from passing a comparison value to `adf_status_str`, which will then print the name of
   a status. Both are as the documents say; the names are far enough apart. Not a defect; noted
   because a binding must not mix the two.

3. **The place handle has no invalid value.** A place is 0 or a prime, so a binding that zeroes a
   handle gets the archimedean place, and there is no way to build a place that names nothing. That
   follows from conventions 7 (the archimedean place first, primes in increasing order, and
   `adf_place_prime_get` returning 0 for the archimedean place, which reserves 0). A later version
   with several places above one prime will need a tie-break (conventions 7 says so: "For fields
   with several places above one prime this order will need a tie-break among them"). Not a defect
   now.

4. **`tests/test_support.c` does not know the vector directory of this lane.** Its table of vector
   files lists the eleven files of `tests/ref/vectors/` and not the twelve of
   `tests/ref/vectors/m1-rat/`, so the reader is exercised on them by `tests/test_rat.c` only. The
   file is not mine. The same goes for `tests/ref/README.md`, whose "Vector format" section should
   mention the subdirectory and the two extra fields of these files (`status` as a name, `num`/`den`
   for a raw pair).

### HEADER-FINDING

None. Every declaration of the three headers could be implemented exactly as written, and no
declaration is ambiguous. Two places where the reading is worth writing down, both in
`include/adelefeld/rat.h` and both followed as the header says:

- `adf_rat_set_fmpq(x, q)` may be given an `fmpq` whose denominator field is 0, which is not a
  value of `fmpq`; the header names `ADF_DOMAIN` for it and the field is public, so the case is
  reachable. It is tested.
- `adf_rat_set_fmpz2(x, num, den)` allows `num` and `den` to be the same `fmpz`; `fmpq_set_fmpz_frac`
  is called with them and gives the value 1 (and `DOMAIN` when both are 0), which the tests check.

## What is not done

- `adf_str_free`, `adf_flint_version_compiled` and `adf_version_check` of `include/adelefeld/common.h`
  are not implemented: `common.h` is not one of the three headers of the brief, no `src/common.c`

- `src/inlines.c` exports the inline functions of all twelve headers, not only the three of this
  lane, because `ADF_INLINES_C` is a library-wide switch. If another lane also creates an
  `inlines.c`, the two must be merged into one file; the symbols would otherwise be defined twice.
- No fuzz target: the lane reads no untrusted text. The parser of the value form arrives with work
  package 1.4.
- The mutation run was not repeated with a smaller `--limit` or another seed; the full run of the
  four files of this lane is 59 s, so it was run once, whole.
